# Задание 2. Разработка дизайна модуля пакетной обработки данных

## Описание ситуации

Каждое утро ровно в шесть онлайн-магазину нужно сгенерировать кастомные CSV/XLS прайс-листы для B2B-клиентов на основе текущих данных в БД. Процесс выгрузки не требует дополнительной логики по обработке данных. 

Данные в PostgreSQL представлены в таблицах:

- `products` ~ 5 000–10 000 строк;
- `categories` ~ 50–200 строк;
- `clients` ~ 100–500 строк;
- `client_prices` ~ 10 000–20 000 строк.

Необходимо связать данные из таблиц и выгрузить их в CSV-файл. Объём данных 5 000–10 000 строк. Инфраструктура магазина — микросервисы в облаке.

## Выбор решения

| Критерий | SpringBatch | Apache AirFlow | K8s Job | Spark |
| --- | --- | --- | --- | --- |
| Наличие конфигурации CRON-расписания | ✅ Spring Scheduler, K8s Job | ✅ | ✅ | ❌, через K8s Job |
| Сложность реализации логики по обработке данных | Легко | Средне | Сложно, реализация полноценного приложения и коннекторов самостоятельно | Средняя, необходим код с использованием Scala/PySpark |
| Ресурсоемкость решения (количество потребляемых ресурсов) | Низкая | Среднее | От низкого до высокого, в зависимости от реализации и выбранной технологии | Высокая |	
| Масштабируемость решения под нагрузкой и сложность реализации | ✅ С помощью Partitioning | ✅ KubernetesExecutor | ❌ | ✅ |
| Сложность развертывания в облаке и интеграция с имеющейся микросервисной архитектурой | ✅ Легко | ✅ Средне, HELM | ✅ Легко | ❌ Высокая |
| Удобство интеграции с системами логирования и мониторинга | ✅ | ✅ | ✅ | ⚠ Требуется ручная настройка необходимых метрик |

Для текущей задачи с ограниченным объемом данных и требованием только одной задачи на выгрузку предпочтительнее выбрать Spring Batch, т.к. решение оптимально расходует ресурсы за счет разбивки данных по чанкам и партициям, что позволит в ближайшее время легко обрабатывать увеличивающийся объем данных.

AirFlow стоит выбрать если потребуется реализовывать с каждым разом все больше и больше процессов выгрузки данных. Для текущей задачи он будет избыточен и потребует более длительного развертывания.

Spark стоит выбирать для обработки больших данных и таблиц, совмещая его с оркестрацией в AirFlow при необходимости подключения разных сервисов и задач обработки данных.

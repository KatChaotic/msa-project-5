### <a name="_qmphm5d6rvi3"></a>**Решение**

![](/out/task-5/results/solution/solution.png)

Для сбора логов принято использовать ELK решение (Elastic + Logstash + Kibana) т.к. они являются распространенным решением и позволяют легко собирать и анализировать логи из разных источников. Подключив сбор логов с помощью Filebeat на уровне Docker можно будет собирать логи сразу со всех развернутых контейнеров и автоматически наполнять их метаданными контейнеров, обеспечивая удобную фильтрацию.

Сбор метрик будет обеспечиваться с помощью Prometheus Exporter Endpoint внутри приложений и Prometheus будет собирать их по указанным путям с заданной периодичностью (раз в 5 секунд).

Для удобного анализа и мониторинга метрик принято решение использовать Grafana т.к. он обладает всеми необходимыми инструментами для достижения поставленных целей: построение дашбордов, алертинг, уведомления.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

В качестве альтернативы можно использовать другой подход к публикации логов, например отправлять логи напрямую из приложения в Logstash. Проблема данного решения в том, что во время критических проблем и краше приложения, ценные логи могут быть не отправлены.

**Недостатки, ограничения, риски**

1. Для развертывания решения требуется задействовать DevOps ресурсы, т.к. состоит из множества компонентов
2. При росте нагрузки и количестве приложений, нагрузка на инфраструктуру мониторинга так же возрастает и может потребоваться её дальнейшее масштабирование (можно снизить риски, настроив политики очистки/архивации устаревших данных, например хранить данные только за последние 2-3 месяца)
